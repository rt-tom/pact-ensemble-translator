## Why

В рабочем каталоге RT D:\pact\book_state помимо четырёх канонических JSON-файлов могут находиться результаты и служебные каталоги других операций. Сейчас MemoryManager.promote() и его транзакционная замена вызывают _validate_exact_four_file_set(): функция перечисляет весь корень и отклоняет посторонний файл или папку. Поэтому локальное обновление состояния может не состояться, а последующая отправка на Media даже не начнётся, хотя клиент уже строит исходящий пакет по четырём явным именам.

Безопасная граница здесь — содержимое четырёх канонических файлов и точный состав исходящего пакета, а не пустота всего рабочего каталога. Посторонние объекты не должны ни блокировать обновление, ни попадать в пакет, ни меняться.

## What Changes

1. Для локального обновления проверять напрямую только glossary.json, book_memory.json, chapter_index.json, observations.json и используемые самой транзакцией известные служебные пути. Убрать перечисление корня и условие «нет других файлов/папок». Отсутствующий, некорректный, не-regular или подменённый канонический файл по-прежнему блокирует операцию.
2. При загрузке авторитетного состояния с Media обновлять только четыре канонических файла и нужные метаданные ревизии (CURRENT.json, manifest.json). Никакие соседние объекты не удалять, не копировать, не валидировать как часть состояния и не перезаписывать.
3. При отправке формировать пакет из явно названных четырёх канонических файлов; манифест и хэши вычислять из тех же зафиксированных байтов. Не делать ни обхода рабочего корня для выбора файлов, ни включения CURRENT.json, локального manifest.json, переводов, журналов или иных объектов в кандидат.
4. Сохранить строгую границу Media: принимаемый кандидат и immutable snapshot содержат ровно четыре файла состояния и созданный для кандидата manifest.json; лишний элемент внутри пакета/кандидата отклоняется. Сохранить проверку родительской ревизии и ограниченный STALE_PARENT retry.

## Capabilities

### Added Capabilities
- book-state-local-sync: обновление и публикация только явного набора канонических файлов при произвольных посторонних объектах в локальном рабочем каталоге.

## Impact

Планируемая реализация — **High risk**: затрагивает запись постоянного состояния книги, транзакционное восстановление и RT↔Media handoff. Меняются локальная проверка book_state и путь подготовки пакета; формат четырёх JSON, схема манифеста, API Media, семантика ACCEPTED/REJECTED и точная проверка входящего кандидата не меняются.

OpenSpec не разрешает удалять или переносить уже лежащие в book_state объекты и не включает доработку форматтера. Реализация, merge, deployment и запуск production-пайплайна остаются отдельными решениями владельца.
