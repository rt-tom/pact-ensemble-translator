## Why

В локальном прогоне book_0001-0001_local_gemma31_qwen38_20260930_072312_487917 было 78 PID с исходными inline-тегами и 102 выделенных фрагмента. Форматтер сделал семь батчей: шесть по 12 PID и один из шести PID. Ветка одного вызова отключилась только из-за фиксированного порога в 80 фрагментов. Часть батчей повторяла одинаковые запросы с маленьким fallback-лимитом 900–1180 токенов; пять батчей исчерпали попытки с finish_reason=length. В отчёте осталось 58 пропущенных привязок.

Задача этапа уже: найти точную русскую подстроку для каждого выделенного английского фрагмента. Само добавление тегов выполняется детерминированно и не должно менять слова перевода. При этом вызов в прогоне не получил политику роли formatting и обошёл предусмотренный для неё потолок ответа. Локальный qwen38 получил серверный бюджет reasoning 8192 на каждый вызов форматтера, несмотря на enable_thinking: false в настройках этапа.

## What Changes

1. Сохранить существующий отбор только PID с исходными inline_spans. Передавать их английский контекст, ID и текст выделенных фрагментов и соответствующий русский перевод одним компактным запросом, когда это позволяет контекст и бюджет ответа. Убрать фиксированные пороги 80 фрагментов и 12 PID для обычного пути.
2. Использовать одну явную политику роли formatting для модели, sampling и потолка ответа. Если политика не разрешилась, записать диагностированный formatting debt без вызова модели через малый старый fallback.
3. Установить фактический бюджет reasoning форматтера в 0 для локального и удалённого транспорта. При локальном вызове reviewer-модель должна запускаться для этой роли с --reasoning-budget 0; бюджеты её остальных ролей не меняются.
4. Если общий запрос велик, собрать минимальное число безопасных групп. При обрезанном или невалидном ответе делить только неудачную группу; при валидном неполном ответе запрашивать только недостающие фрагменты. Не повторять идентичный запрос, уже упершийся в лимит.
5. Сохранить проверку точной подстроки и occurrence, детерминированную вставку тегов, мягкий debt для неразрешённых фрагментов и текущие формы translations.json и formatting_report.json. Сохранять диагностику каждой фактической попытки.

## Capabilities

### Modified Capabilities
- book-production-formatting: компактный запрос на размеченные PID, бюджет из политики роли, адаптивное деление и адресное восстановление.
- local-model-registry: явное исключение reasoning=0 только для роли formatting из правила «бюджет модели + добавка роли».

## Impact

Риск высокий: меняются оркестрация форматирования и локальная маршрутизация модели. Промпт переводчика, слова перевода, контракт PID и продвижение book_state/Media не входят в эту задачу. Прежний OpenSpec по форматтеру уже предусматривал один вызов и reasoning=0; это предложение устраняет обнаруженное расхождение с нынешней реализацией local-matrix-v2.

Завершённые главы не пересобираются автоматически. Новая версия политики действует при свежем этапе форматирования или явно запрошенном повторе. Миграции артефактов и запуска production-пайплайна в этой задаче нет. Реализация, merge, deployment и запуск пайплайна требуют отдельных решений владельца.
