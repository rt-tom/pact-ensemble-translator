## Decision frame

Owner confirmed the expensive stage is `entity_extractor` (B1.2), not the separate glossary resolver, and selected compact source-matched hints rather than skipping known entities. Baseline today: `render_entity_extraction_prompt(chapter_id, source)` receives source PIDs only, `BackendEntityExtractor` sends one user message, and `entity_context_cache_key` binds only `source_hash + extractor_version`. The runner already loads pre-chapter `ChapterMemory`, renders bible text for other roles, and in the optional role-view path calls `select_relevant` before B1.2. Reuse deterministic relevance ideas, NOT a full role-view/bible dump. No reason to change generation/audit prompts, resolver, model routing or reasoning budgets in this change.

## 1. Compact card before B1.2

From the frozen memory/glossary loaded before generation, collect names and vetted source aliases in `characters`/`entities`/`terms` and `GlossaryEntry.source_term`. Check each English surface with token/word boundaries against the current ordered source PID map; exclude conflicts (`_conflicts`, `_excluded_conflict`, disagreement between glossary and memory canonical Russian forms), candidate-only observations, global exceptions with no source presence, and unmapped words. Use the existing glossary/memory conflict rules to exclude ambiguous identities, but do not pass Russian forms: B1.2 emits English-source claims, not translations. Render short structured rows `source surface -> canonical English identity` with an unmistakable `PRIOR HINTS — NOT SOURCE EVIDENCE` header. No full prose facts, memory IDs from another book, unmatched entries or source text duplication. Stable selection: earliest source PID/offset, then casefolded canonical key; deduplicate; proposed cap **32 rows / 2048 rendered characters** including header. If over cap, truncate deterministically and expose counts/hash in diagnostic metadata; truncated items simply receive the unchanged source-only treatment. These limits are proposed defaults for owner review, not measured savings claims.

Keep the card internal: no new source-format or output-book contract. The card is built once per chapter and passed to both the pre-generation B1.2 call and the B3 invocation, without recomputing after intra-chapter observations. The optional `book_memory_role_views_enabled` path may reuse its precomputed relevance result, but the feature must also work in the default path without turning on role views globally.

## 2. Prompt and evidence boundary

Append only the small prior-hint card to the B1.2 request. Instruct the model to use hints only to orient source reading, never as justification to omit an entity when this chapter establishes a new alias/role or contradicts the hint. Maintain the original strict response JSON schema, full chapter PID map, source-only anchor and evidence requirements and validation before any downstream generation/audit/promotion. No book-memory fact may be stamped `verified` from prior context; unconfirmed same-entity links remain `candidate` (Tier B). For an empty card preserve the original source-only prompt byte-for-byte where possible.

## 3. Cache / resume safety

Use a canonical hash of the **exact rendered card and prompt variant** in the B1.2 cache key when non-empty, alongside source hash and extractor version. Reuse current source-only key for empty-card calls only if that prompt/validator is exactly the original; otherwise bump version and invalidate old cache safely. Propagate the same card identity to the prepass and subsequent B3 run, plus the stage/resume identity where extraction reuse occurs. A changed *irrelevant* memory entry must not change the rendered card or trigger re-extraction; a changed relevant source identity/alias must. An unrelated Russian spelling change that does not alter the card must not invalidate B1.2. Do not accept an old source-only cache entry under the hinted key. Keep existing validation of every cache hit and old artifacts readable; no bulk rebuild/migration of persistent state.

## 4. Verification and deployment boundary

Focused offline tests for matching (casefold, punctuation, aliases, word boundaries), authority/conflicts, cap and deterministic order, source-only output/validators, changed-hint invalidation, empty-card baseline, same-chapter B3 zero-extra-call replay and memory-drift resume. Add static fidelity lint. Record per-role usage for existing and future owner-approved A/B run as input/reasoning/output plus error/validation counts. Lower cost/latency is a hypothesis, not an acceptance claim from static tests. Any RT run, source text transfer, deployment or state change is separately approved by the owner.
