# v3.1.3 mandatory task: explicit MODEL_REQUIRED stage protocol

## Status

Mandatory before model-start skipping is extended beyond stages whose current
top-level Python guard guarantees aggregate reuse.

## Required contract

- Every model-capable stage must support a model-free probe/run mode with
  structured outcomes such as `REUSED`, `MODEL_REQUIRED`, and `FAILED`.
- `MODEL_REQUIRED` must be emitted through a machine-readable status channel
  with a defined exit code and payload; the runner must never infer it from an
  exception message or log text.
- On `MODEL_REQUIRED`, the runner starts the required owned profile and repeats
  the same stage once under the normal execution path.
- The protocol must distinguish aggregate completeness from partial cache
  availability. Partial caches never authorize model startup skip.
- The protocol must have offline contract tests in every participating Python
  stage and runner tests covering retry, invalid outcomes, and force flags.

## Current boundary

v3.1.2j may skip startup only for source analysis, audits, cross-verification,
repair generation, and postchecks when every selected chapter already has the
exact aggregate file checked by that stage's top-level `exists && !force`
guard. Translation is excluded.
