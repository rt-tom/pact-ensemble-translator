# V4: анализ провалов v3 на главе 100 и усиление слабых мест

Дата: 2026-08-01. Статус: design-note / анализ. Реализация — отдельными карточками
по решению после benchmark (§10 Q5 MVP-спеки и ниже).

Источник: независимое внешнее ревью перевода главы 100 (вывод v3) от сторонней
модели; вердикт ревью — «неприемлемо». Блокеры: смена грамматического рода
рассказчика в середине главы, подстановка имени другого персонажа саги
(«Цирюльник» вместо «Человек с часами») и инверсии смысла в нескольких местах.
Все три категории кластеризуются в одном участке главы (~абзацы 144–213), что
указывает на стык чанков, где не сработала передача контекста.

---

## 1. Почему v3 пропустил эти ошибки

### 1.1. Ревьюер — та же модель, что переводила

`reviewer_api.model` = Gemma-4-26B-A4B-it-UD-Q4_K_XL.gguf — ровно та же, что и
`translator_api.model` (`pact_translate_v3.py:30-52`). Внутриплюсный ревью — это
self-review той же модели: коррелированный сигнал, не независимое доказательство
качества. Он структурно не может увидеть дрейф рода/терминов, который сам же
сгенерировал.

### 1.2. Структурная слепота к швам

`make_audit_units` (`pact_translate_v3.py:2220-2237`) режет **те же** трансляционные
чанки на батчи по `audit.batch_pids=8` PID с контекстом
`audit.context_before/after=2` блока (`pact_translate_v3.py:94-111`, `2090-2099`).
Граница трансляционного чанка никогда не оказывается центром юнита ревью — оба
конца шва одновременно не видны. Плюс потолок `max_issues_per_batch=5` и
инструкция «не отмечай допустимые стилистические варианты» консервативно
подавляют замечания. Гипотеза рецензента из конца отчёта подтверждается кодом.

### 1.3. Голос и термины не замораживаются на главу

Переводчик на чанк получает 3 предыдущих + 2 следующих исходных блока и 2
релевантных ранее (`chunk_context`, `pact_translate_v3.py:1123-1167`), RU
left-context — максимум 3 блока уже переведённого. Ничто не фиксирует для всей
главы «рассказчик — Блэйк, мужчина, первое лицо» или «clock man = Человек с
часами». Каждый чанк заново угадывает голос и термины → дрейф на стыках.

### 1.4. Детерминированные слои слишком узкие

- `narrator_gender_check` (`pact_translate_v3.py:2050-2074`) — whitelist из ~8
  глаголов и работает только при `chapter_bible.pov.gender == "male"`. «воспользовалась»,
  «ждала», «поднялась» и т.п. туда не входят.
- `entity_check` пропускает строчные source-термины через `source[:1].isupper()`
  (`pact_translate_v3.py:2001-2022`) — «the clock man» (строчная) не проверялся
  вообще, поэтому 5 вариантов перевода термина детерминированно не ловились.
- Инверсии смысла (#1-5, #10, #15 из ревью) не имеют независимого семантического
  гейта вообще — только тот же Gemma-ревьюер.

## 2. Оценка: какие классы ошибок v4 поймает

### 2.1. Поймает надёжно (структурно)

| Класс | Механизм v4 |
|---|---|
| Инверсии смысла, референты, идиомы | Risk-прескрин флагает `idiom_or_metaphor`, `ambiguous_referent`, `negation` (`pact_v4/phase2/risk.py:55-59`) → A/B + глубокий Qwen-анализ. Qwen semantic admission — **другая модель, чем генератор Gemma** (независимый сигнал), явно проверяет subject/object/negation/modal/referents/idioms. Assembled-chapter Qwen-аудит (Step 6) видит всю главу |
| Дрейф терминологии | Дискурс-план Qwen (Step 3) один раз фиксирует термин/имя на главу; детерминированный glossary/name-чек идёт по всей собранной главе **без** капс-фильтра v3 (`pact_v4/phase3/audit.py:352-408`) |
| HTML/разметка, mixed-script | Детерминированно и по всей главе, до финального степа (Step 6/8) |
| Внутриглавная несогласованность | Собранная глава — один и тот же EN-фрагмент виден в разных местах одному аудиту |

### 2.2. Остаются слабыми

| Класс | Почему | Что закрывает частично |
|---|---|---|
| Род рассказчика | Qwen **не может** это поймать: в EN «I» не несёт рода, сравнивать с исходником не с чем | book_memory + дискурс-план, фиксирующий «первое лицо, мужской род» + Russian-only ревью Gemma по собранной главе. Но Gemma-ревью — коррелированный сигнал; его судьба висит на §10 Q5 |
| Русский регистр/кальки/опечатки | Только Gemma Russian review/preference, та же модель, ablation-pending | Улучшено (вся глава в одном обзоре), не гарантировано |
| «Цирюльник» как подмена термина | «Цирюльник» — легитимное имя другого персонажа (the Barber), name-gate его принимает | Только семантика (Qwen) / русское ревью; надёжнее при локе «clock man» |

### 2.3. Статус внедрения

Assembled-chapter аудит (Step 6) реализован (`pact_v4/phase3/audit.py`), но **не
подключён** к strict single-resident драйверу (DECISIONS 2026-08-01); оптимизация
порядка циклов `for detector → for chunk` — известный TODO. Q5-ablation по
самостоятельности Gemma Russian review не прогнан. То есть «способна» —
архитектурно да; операционно Phase 3 end-to-end ещё не работает.

## 3. Усиление слабых мест

### 3.1. Детерминированные (без моделей, дёшево, сразу)

**1.1. Морфологическое правило рода рассказчика.** Обобщение v3-whitelist:
«я» + глагол прош. времени на `-ла`/`-лась` — безальтернативно женское
согласование (мужское было бы `-л`/`-лся`). Скан по всей собранной главе в
Step 6/8 поймал бы все 9 случаев из ревью #25. Скоуп — POV-абзацы по плану.
Высокая точность; в v4 в детерминированном слое отсутствует вовсе.

**1.2. Модовая терминологическая проверка.** Текущий чек сверяет только с
locked-формой. Добавить chapter-wide сверку «против моды»: EN-термин, встречающийся
≥2 раз → собрать варианты перевода по PID, флагать варианты-одиночки против
доминирующего. Работает **без лока** (PID-выравнивание точное); ловит и 5
вариантов «clock man», и единичный «отпечаток». Не знает, какой вариант верный,
но находит само расхождение — уже finding.

**1.3. Cross-name substitution.** Известное имя Y в target при отсутствии Y в
source → «неожиданное устоявшееся имя, возможна подмена персонажа». Ловит
«Цирюльник без Barber в исходнике» — случай, невидимый независимой проверке
терминов.

**1.4. Орфографический скан локальным словарём.** `навстрев`, `встретившившись`,
`искрнуло`, `безчасовую` — класс, ненадёжный для LLM-ревью, но тривиальный для
pymorphy3/hunspell + OpenCorpora как неизвестные слова. Детерминированный проход
по собранной главе.

**1.5. Seam-pair audit units.** В Step 6 «центральным» юнитом сделать сам шов
(хвост чанка N + голова чанка N+1) хотя бы для risk-помеченных границ — шов как
объект первого класса, а не побочный продукт перекрытия.

**1.6. Few-shot негативные примеры в audit-промптах.** Прокинуть в промпты Qwen-
и Gemma-ревью по 1-2 примера на класс реальных провалов (дрейф рода, одиночный
вариант термина, подмена имени, двойное значение идиомы в главе, инверсия).
Дёшево, бьёт по recall конкретных классов.

### 3.2. Умеренные (в рамках текущей пары Gemma/Qwen)

**2.1. Qwen как второй русский ревьюер.** Qwen уже грузится в Step 6 для EN↔RU;
отдельный RU-only проход тем же Qwen — второй, независимый от Gemma сигнал по
стилю/регистру/калькам/порядку слов, без третьей модели. Фактически решает §10 Q5
за счёт силы модели.

**2.2. «Гендерные улики» в дискурс-плане.** Step 3 должен не просто писать
«рассказчик — мужчина», а собрать из исходника референсы к нему (`he/him/his`,
«Mr. Thorburn») с PID-пруфами и заморозить как handoff-ограничение с явным «все
глаголы первого лица — мужской род» — якорь для генератора вместо абстрактной
инструкции.

### 3.3. Измерительное / стратегическое

- Прогнать §10 Q5 ablation (даёт ли Gemma Russian review recall, или его съедает
  корреляция) до решений по 1.6/2.1.
- Засеять golden set из внешнего ревью главы 100 — конкретные known_violations по
  этим классам, чтобы semantic recall стал измеримой метрикой Phase 0.
- Третья модель как эскалация, не blanket: RU-only ревью сторонней моделью только
  для риск-помеченных глав (плотный диалог, переходы сцен, термин-шторм). Spec
  допускает опц. 3-ю модель в Phase 6+.

Приоритет: 1.1 + 1.2 + 1.3 закрывают самый хрупкий класс (род) и самые коварные
(дрейф терминов) без единого нового model call; далее 1.4/1.5/1.6; затем 2.1/2.2;
третья модель — последней, всё на результатах Q5 ablation.
